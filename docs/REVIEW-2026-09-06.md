# Review findings

## 1. Content-Range arithmetic can overflow

`parse_content_range` accepted `bytes 0-18446744073709551615/*`, causing `end - start + 1` to overflow. Reproduced through the public response API after successfully encoding a valid request. Status: corrected at the parser boundary: `start <= end < u64::MAX`, plus `end < total` when known. Downstream arithmetic remains ordinary. Added boundary regression tests.

## 2. Multipart 412 responses conflate leases and ETag conditions

The initial multipart implementation rejects every stage HTTP 412 as a protocol fault and treats every conditional commit HTTP 412 as an ETag mismatch. Azure lease failures also use 412. Classification must inspect the native code and request the error body when it is missing. Status: corrected; native code and saved condition now distinguish lease failures, missing codes, and ETag mismatches.

## 3. Request-size counting uses unchecked addition

`request::Writer::push` adds each borrowed value's length to a `usize` counter. Repeated large borrowed values can overflow even when the destination is empty, especially on 32-bit targets. Variable metadata increases the reachable input space. Status: corrected; byte and descriptor counts saturate. Encoders return `InvalidPlan::RequestTooLarge` when either the byte buffer or descriptor array would exceed the target's `isize::MAX` slice boundary. Regression tests cover both limits and counter overflow; the descriptor-size check runs only on the capacity-error path.

## 4. Curl host's memory comment excludes libcurl's own header storage

Modern libcurl keeps response headers for [curl_easy_header](https://curl.se/libcurl/c/curl_easy_header.html), so the host arena is additional storage. `Limits::head_bytes` bounds only that arena, not descriptors or libcurl memory. Status: misleading memory and allocation comments corrected. The arena remains because returned response fields outlive the per-request easy handle; switching to borrowed libcurl headers would require changing handle ownership.

## 5. Curl listing bodies have no byte budget

`collect_page` in `hosts/cxx-curl/curl_host.cc` appends every received byte to a vector without a cap. The parser runs after download. A requested entry count does not bound entry lengths or malformed response size; multipart block listing has no page-size hint at all. Status: accepted for this compatibility example. Download limits are host policy, outside the core's full-buffer parsing contract. No byte limit is planned here.

## 6. C benchmark labels a checksum as an entry count

The `with` function in `bench/c/bench.c` returned `fill.filled + (seen != 0)` to keep property reads observable, incorrectly reporting 5,065 for 5,064 entries. Status: corrected; the checksum has a separate volatile sink, and the function returns the actual entry count.

## 7. A public suffix shape reaches unreachable response code

`accept_get_head` accepted a caller-created `GetShape` without prior encoding. A suffix shape with HTTP 206 reached `unreachable!`; request-side rejection did not establish a response-side invariant. Reproduced through the public API. Status: corrected; the response returns `ResponseFault::Range`. Added a regression test.
